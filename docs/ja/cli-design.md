# CLIコマンド体系の設計

この文書では、txBASEのコマンド体系を設計した判断を記録します。

コマンド契約、引数表、オプションの所有範囲は[CLIコマンドリファレンス](cli.md)に記載します。

## 明示的なサブコマンド

txBASEは、パスを開く前にコマンドの責務が分かるよう、明示的なサブコマンドを使います。

最初のトークンで1つの責務を選び、`mvcc`、`wal`、`xbf`、`index`のようなライフサイクルを持つ機能群は入れ子のサブコマンドでまとめます。

対象が一意な操作では、パスとJSON値を位置引数にします。

`--encoding`、`--schema`、`--bind`、`--keep`、`--keep-rows`のように解釈または有界な方針を変えるものは、名前付きオプションにします。

## Gitを参照する範囲

Gitのコマンドラインインターフェース文書は、明示的なサブコマンドと名前付きオプションの参照資料です。

txBASEは、Gitのコマンド群、リポジトリモデル、リビジョン言語、オブジェクトデータベース、オプションの意味をコピーしません。

共通するのは構造だけです。
txBASEが扱う対象は、Gitリポジトリではなく、DBFファイル、カタログディレクトリ、サイドカー、ローカル復旧境界です。

## 失敗境界への配置

コマンドは、失敗時の動作と決定的なフィクスチャが一致する最小の責務グループに配置します。

読み取り指向のコマンドは、通常の復旧がディスク上の状態を変更し得るかを明記します。

`wal inspect`は、WALを作成または切り詰めずに完全なレコードと不完全な末尾を報告するため、非更新の例外です。

更新コマンドは、DBF、カタログ、XBFの操作が所有するロック、復旧、ジャーナルの経路を再利用します。

サイドカーだけを変更するコマンドは、ヘルプとトピック文書でそのことを明記します。

## 互換性の境界

馴染みのあるコマンド名だけで、dBASE、MongoDB、Git、SQLiteとの互換性を主張しません。

CLIはリポジトリ固有の有界なサブセットを公開し、各コマンドの文書で入力上限、復旧動作、書き込み対象、失敗時のステータスを定義します。
